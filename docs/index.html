TOKEN PIPELINE

钱花在哪，就从哪下手

input 常占账单 60–90%

三段机制互不重复、可叠加：Headroom 管「进什么」，Caveman 管「说什么」，Ponytail 管「写什么」。 以典型会话 input 80% / output 20% 计，三者叠加后整单可接近直接相加地下降。

THREE PILLARS

三件套，各管一段

市面工具多各自为战。这个 Skill 把原理、决策树、检查清单、安装命令合成一份 Playbook，供 Cursor / Claude Code / Codex 按需加载。

HEADROOM

压「进模型的输入」

Proxy / MCP 压缩日志、JSON、文件、历史上下文；CCR 可逆检索，不丢决策所需信息。

上下文 -60% ~ -95%
CAVEMAN

砍「自然语言废话」

解释、总结、Review 全部去水；代码 / 命令 / 报错保持字节级原样。强度 lite / full / ultra 可调。

输出 prose ~ -65%
PONYTAIL

瘦「生成的代码」

写码前走七级梯：YAGNI → 复用 → 标准库 → 原生 → 已有依赖 → 一行 → 最小实现。

LOC -54% · tokens -22%
DIAGNOSE

账单高？先定位瓶颈

大多数 Agent 会话的瓶颈在 input，不是 output。按下面的决策树 30 秒定位。

START
Agent 账单 / compaction 频率是否偏高？
工具读回日志 / 大文件多

→ Headroom + 输入优化：日志只看 tail / ERROR，大 JSON 只取相关字段，.cursorignore 排除噪音。

回复解释很长

→ Caveman + 输出优化：结论先行、列表代替段落、/caveman-review 一行式。

生成代码臃肿

→ Ponytail 七级梯 + /ponytail-review 对 diff 做 over-engineering 审计。

多轮历史 / MCP schema 长

→ 分任务开新会话 + claude-mem 外置记忆 + caveman-shrink 压缩 MCP 描述。

INSTALL

  
一条命令，装好三件套

  

    

      
本 Skill（Playbook 本体）

      
Cursor 全局安装，对话中 @agent-token-efficiency 即触发诊断流程。

      

        

          

          install.sh
          
        

        
# 全局安装到 Cursor
npx skills add Keep-maker/agent-token-efficiency-skill --agent cursor -g -y

      

    

    

      
三件套一键（可选）

      
与本 Skill 配合，覆盖输入、prose、代码三段。装完跑验证命令。

      

        

          

          three-pillars.sh
          
        

        
npx skills add DietrichGebert/ponytail -g -a "*" -y
npx skills add JuliusBrussee/caveman -g -a "*" -y
pip install "headroom-ai" "httpx[http2]"
headroom wrap cursor          # 自动注册 proxy
headroom proxy --port 8787    # 启动（可选）
headroom mcp install          # MCP: compress / retrieve / stats
